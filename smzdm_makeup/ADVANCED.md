# 什么值得买排队补签（青龙 / Node.js）

按顺序给多个账号补回漏签日期。默认只查询；明确开启后才消耗补签卡。每次最多补一天，随机等待 5–15 秒。支持账号选择、总上限、每个账号独立上限、断点记录和 Bark 结果通知。

这是补签脚本，不执行每日签到、抽奖、评论或领卡。服务端选择下一次可补的日期；脚本不能指定任意一天。5–15 秒是初始配置，不保证适用于所有账号或未来接口；触发频率限制会停止。

## 1. 青龙安装

在青龙「订阅管理」添加 Git 仓库：

- 地址：`https://github.com/text1235/Script.git`
- 分支：`main`
- 白名单：`smzdm_makeup.js`

或运行拉库命令：

```bash
ql repo https://github.com/text1235/Script.git "smzdm_makeup.js" "" "" "main"
```

在「依赖管理 → NodeJS」安装 `got@11`。运行环境需要 Node.js 20 或以上。脚本为单文件，不依赖你手机上的 Debian 路径或另一个脚本仓库。

## 2. 配置 Cookie（支持多账号）

在「环境变量」添加 `SMZDM_COOKIE`，值为你自己的什么值得买 App Cookie。Cookie 要包含 `sess` 与 `smzdm_id`。多个账号可以用 `&` 或换行分隔，也可在青龙添加多个同名变量（由青龙的环境加载功能合并）。账号序号从 1 开始，按合并后的顺序计算。

```text
账号1完整Cookie&账号2完整Cookie&账号3完整Cookie
```

Cookie 只保存在自己的青龙环境变量中，不要写进脚本或上传 GitHub。不要把真实 Cookie 放进问题反馈、截图或运行日志。

## 3. 先查询，确认顺序与卡数

找到拉取后的 `smzdm_makeup.js`，手动运行。未设置 `SMZDM_BACKFILL_APPLY=1` 时只查询，不用卡。输出包括账号序号、下次可补日期、连续签到天数及接口返回卡数。

查询默认遍历所有账号。环境变量 `SMZDM_BACKFILL_ACCOUNTS=2,3` 可只查第 2、3 个账号。

## 4. 开启真实补签

添加下面环境变量。示例是三个账号各最多用 10 张，合计最多 30 张；请按自己的需求改数字。

| 变量 | 示例值 | 含义 |
| --- | --- | --- |
| `SMZDM_BACKFILL_APPLY` | `1` | 明确开启真实补签 |
| `SMZDM_BACKFILL_ACCOUNTS` | `1,2,3` | 选择账号；`all` 表示当前全部账号 |
| `SMZDM_BACKFILL_BATCH` | `makeup-20261009` | 批次标识，恢复时保持不变 |
| `SMZDM_BACKFILL_MAX_CARDS` | `30` | 本批所有账号合计的尝试上限，1–500 |
| `SMZDM_BACKFILL_LIMITS` | `1:10,2:10,3:10` | 每个账号的尝试上限，需列全所选账号；可用 0 排除用卡 |
| `SMZDM_BACKFILL_LOOP` | `1` | 在一个进程内持续排队；不设则每次最多补 1 张 |
| `SMZDM_BACKFILL_STATE_DIR` | `/ql/data/smzdm_makeup_state` | 持久状态目录，建议明确配置 |

`SMZDM_BACKFILL_LIMITS` 可省略，此时只受总上限限制。建议多账号时设置独立上限，避免顺序变化或卡数变化导致用卡超出预期。输入的上限是请求次数；结果不明的请求仍计入上限。运行中新增、奖励得到的卡不会提高你的配置上限。

在「定时任务」新建任务，命令填写拉取后的脚本实际路径（见下方示例），定时规则设成 **仅运行一次（`@once`）**，开启禁止多实例，然后手动运行。循环会在手机或服务器的青龙进程中持续执行。**不要设置每分钟重复启动循环，不要反复点击运行**：某些青龙版本会停止旧任务再启动新任务。开启禁止多实例，并保留脚本的锁文件保护。

实际命令路径以「脚本管理」拉取的路径为准，例如：

```bash
task text1235_Script_main/smzdm_makeup/smzdm_makeup.js
```

未使用循环时，单次调用最多提交一张，间隔和预算仍由持久状态控制。

## 5. 结果与通知

脚本输出每次补回日期、本批已确认数量、已尝试数量和上限。选中账号轮流执行；一个账号用完卡或达到独立上限后跳过，继续其他账号。全部完成或达到总上限后退出。

可选 Bark 环境变量：

| 变量 | 内容 |
| --- | --- |
| `BARK_PUSH` | 自己的完整 Bark 推送地址 |
| `BARK_GROUP` | 可选，默认 `qinglong` |

只在本批结束或暂停时推送汇总，不每补一天都推送。未配置 Bark 不影响补签。推送内容有账号序号、次数和剩余卡数；只发到你配置的地址。

## 6. 暂停、恢复和不明结果

触发频率限制、服务器拒绝、网络超时或补签后的状态不符时，保存状态并暂停。消耗卡的 POST **不自动重试**。状态查询可在成功后额外只读重查两次，以容纳服务端短暂延迟。

恢复时保持同一批次、账号顺序、账号上限、总上限和状态目录。完成的批次再次运行也不会继续用卡。**不要通过删除状态、改批次或删锁来重复提交结果不明的请求。**

若日志显示服务器已接受，但后续状态未确认，可以设置 `SMZDM_BACKFILL_RECONCILE=1`，用同一套参数手动运行一次：此模式仅查询状态并核验最后一笔，不调用补签接口。只有下一日期已经推进、连续签到天数达到预期时才解除暂停；卡耗尽时，以官方“没有补签卡”回复与签到页天数增长一起核验。核验后删除该变量，再运行原任务。若仍无法核验，应在 App 人工检查；频率拒绝或未明确接受的请求不能用此模式自动恢复。

意外停机可能留下 `running.lock`。须确认对应进程已结束，并检查 `state.json` 有无 `pending`；有待确认请求时先核对实际签到。不要在进程还活着时移除锁。

## 普通 Node.js 使用

下载本目录，在终端运行：

```bash
npm install
# 通过自己的环境配置 SMZDM_COOKIE；默认仅查询
node smzdm_makeup.js
npm test
```

Node.js 无需青龙。若青龙默认环境预加载文件不存在，脚本直接读取进程环境；其他部署可设置 `SMZDM_BACKFILL_PRELOAD` 为实际文件路径。状态目录默认为脚本目录的 `.smzdm_makeup_state`，可用 `SMZDM_BACKFILL_STATE_DIR` 改为持久、可写目录。
